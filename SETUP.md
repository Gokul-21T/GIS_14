# GIS Land Governance MVP — setup and recovery

This guide is for restoring and running this project on Windows after moving it to Drive or resetting the laptop.

## What you need

This is a JavaScript/React web application. It does **not** use Python, `pip`, or a Python `requirements.txt`. The equivalent dependency files are:

- `package.json` — project scripts and JavaScript packages.
- `package-lock.json` — locked package versions used by `npm ci`.

The app uses Node.js/npm, React, Vite, Leaflet, and React-Leaflet. Map tiles come from OpenStreetMap when you have an internet connection.

### Runtime included in this project

The project currently contains a portable Node.js 22.14.0 x64 runtime at `.tools/node-v22.14.0-win-x64/` (`node.exe`, `npm.cmd`). If that folder is present after restoring your backup, a separate Node.js installation is not required. Keep `.tools` with the project. If you prefer a system install, install Node.js 22 LTS or newer, then use `node` and `npm` directly in the commands below.

## Restore and install

1. Copy the complete `GIS` project folder from your backup to a normal local folder, for example `D:\GIS` or `C:\Users\<your-user>\Projects\GIS`. Avoid running it directly from a cloud-sync placeholder or a compressed ZIP.
2. Open PowerShell and change to the folder where `package.json` is located. For the example path:

   ```powershell
   cd D:\GIS
   ```

3. Use the included runtime by adding it to this PowerShell session's `PATH`:

   ```powershell
   $env:PATH = "$PWD\.tools\node-v22.14.0-win-x64;$env:PATH"
   node --version
   npm --version
   ```

   If you installed Node.js separately or `.tools` is not present, skip the `PATH` line and use your installed `node`/`npm`. Check they are available with `node --version` and `npm --version`.

4. Restore the packages exactly from the lock file:

   ```powershell
   npm ci
   ```

   This downloads packages from the npm registry, so internet access is needed for installation. `node_modules` is generated by this step; it does not need to be backed up.

## Run the development app

From the project folder, with the runtime on `PATH` as above:

```powershell
npm run dev
```

Open the local address Vite prints (usually `http://localhost:5173/`) in a browser. Leave the PowerShell window running while using the app. Press `Ctrl+C` in that window to stop it.

## Other project commands

```powershell
# Create an optimized production build in dist\
npm run build

# Serve the production build locally (run build first)
npm run preview
```

## Optional: make the runtime PATH setting permanent

The commands above set `PATH` only for the current PowerShell window. To use the included runtime in future PowerShell windows without reinstalling Node.js, add the actual runtime folder to your Windows user `Path` environment variable:

```text
D:\GIS\.tools\node-v22.14.0-win-x64
```

Change the path if you copied the project somewhere else. Alternatively, run the session-only `$env:PATH = ...` command each time. Do not add the project folder itself to `PATH`.

## What to preserve in your backup

Preserve the whole project folder, especially `package.json`, `package-lock.json`, `src\`, `index.html`, and `.tools\node-v22.14.0-win-x64\` if you want the bundled runtime. `node_modules\` and `dist\` can be recreated (`npm ci` and `npm run build` respectively), so they are optional backup items. Keep `src\data\` because it contains the demo parcel and land-record data.

The project uses demonstration data only; its boundaries and records are not official cadastral data.
